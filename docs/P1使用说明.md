# P1：角色与稳定底座

当前角色文件：characters/xu_zhining.md。修改后需重启聊天程序生效，无需重启 NapCat。

## 本机 PowerShell

在项目目录执行：

```powershell
pwsh -File .\scripts\bot.ps1 status
pwsh -File .\scripts\bot.ps1 start
pwsh -File .\scripts\bot.ps1 restart
pwsh -File .\scripts\bot.ps1 stop
```

脚本只管理本项目虚拟环境下的聊天进程；停止不会停止QQ。停止会中断尚未处理完的消息，重启后不自动重发，以免重复发送。
本机.env必须配置ALLOWED_QQ_USERS（逗号分隔），只允许这些账号私聊；不得把真实凭据或用户号码写进角色文件和文档。

## 本轮能力与限制

- 私聊按用户排队，最多30条待处理；队列满后尝试发送繁忙提示。未接收的那条需用户重发。连续短消息合并尚未实现。
- 最近6轮、最多12条已确认送达消息用于上下文，数据库本机持久化，超过30天在启动或下次处理消息时清理。
- 错误提示、未确认送达和失败回复不作为共同经历；不自动重发不确定的消息。
- 每个机器人账号与用户每天最多100次模型调用尝试，使用北京时间，重启不重置；调用失败也消耗次数，避免失败循环。
- 本轮不是长期记忆：没有事实提取、语义回忆、摘要、关系自动成长或记忆管理命令。
- 更新前原型只存在内存的对话无法自动迁移；新版本从启用后开始积累上下文。
- 日志不主动记录正文，但SQLite包含聊天正文，未做数据库加密；由操作系统用户权限保护，不进入Git。
- 数据库被删除会同时清空上下文、去重记录与额度，请勿作为日常重启方式。

## 验证

离线：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v`。
线上：观察READY及ONEBOT_CONNECTED，然后主人从授权主号发送测试消息。只有新消息的模型生成、发送成功回执和用户实际收到一起确认后，才算本版本QQ端到端验收。
