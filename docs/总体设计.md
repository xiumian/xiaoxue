# 许知宁陪伴机器人总体设计 V1

日期：2026-10-25。状态：设计基线，未实现部分不得视为交付。

## 目标与现状

目标：先在 QQ 私聊实现具有稳定角色、可培养偏好与可管理记忆的陪伴角色，未来复用核心接入语音和 App。
角色：许知宁，21 岁成年女性角色。温柔微甜、有主见；初识即友好，逐渐亲近；恋爱关系需明确确认，不按次数解锁。
不设父女关系，不伪称现实真人或真实意识，不编造共同经历，不用失联惩罚或排他性话术维系互动。

已确认：Python 原型和 NapCat 完成 QQ 私聊往返，用户已确认收到回复；DeepSeek 生成曾通过实测。此为历史验收，不保证后续进程持续在线。
尚未实现：许知宁正式角色配置、长期记忆、关系状态、语音、App。当前 bot.py 仍使用小禾提示词和内存内最近六轮上下文。

## 架构与模块

QQ/NapCat → 平台适配器 → 身份与消息队列 → 对话编排 → 模型服务 → 发送回执。
对话编排按需读取角色、最近上下文、相关记忆和明确关系状态。

1. adapters：将平台消息转为统一事件；校验 OneBot 令牌；发送并关联回执。
2. dialogue：按用户排队、短消息合并、去重、超时和错误恢复。不得通过丢弃忙时消息控制并发。
3. persona：加载角色版本、表达示例与明确偏好；核心设定只允许授权修改。
4. memory：SQLite 持久化、全文检索、候选筛选、冲突检查、修订与删除。
5. relationship：保存确认的关系阶段、称呼边界、约定；不设自动增长好感分。
6. providers：封装模型与未来语音 API，平台适配器不依赖模型细节。
7. scripts：启动、停止、状态、备份恢复；只管理本项目进程。

统一事件字段：platform、account_id、conversation_id、user_id、message_id、timestamp、segments。状态隔离键为平台、机器人账号、会话、用户及角色的组合；私聊与群聊不得共享私密上下文。
App 账号需用户主动绑定；未绑定不得依据昵称合并身份。

## 人格与培养

角色文件区分身份、核心原则、表达习惯、虚构背景及示例。
角色喜好属于设定；真实用户事实、模型推测另存。不得用虚构背景声称刚在现实完成某事。
普通聊天不能覆盖角色核心；用户反馈先记为候选表达偏好，明确指令可确认更新。每次配置变更保留版本与原因，可回滚。
回复应口语化、可长可短、有不同意见；不机械追问，不重复客服式安慰；不以故意错字、假装真人活动制造真实感。

## 记忆设计

初期 SQLite 与 FTS5；部署时探测 FTS5 支持，不可用时明确报错，不静默丢失检索功能。暂不引入向量数据库。

逻辑表：
- identities：平台身份、用户授权与显式账号绑定。
- messages：事件 ID、隔离键、时间、方向、正文和发送状态。
- summaries：阶段摘要、来源消息范围、生成时间与版本。
- memories：内容、类型、隔离键、事件时间、来源、确认状态、敏感级别、有效期、修订版本和删除状态。
- memory_sources：记忆与来源消息关联。
- relationship_state：明确关系阶段、称呼及边界、来源和版本。
- preferences：确认的表达偏好及来源。
- usage：按日期与用户统计调用，重启不清零。
- deletions：不含被删除正文的删除标识，用于恢复备份后重放删除。

记忆分为用户事实、共同事件、明确约定；近期情绪默认不转为永久人格标签。
写入：提取候选 → 来源核对 → 敏感信息确认 → 去重与冲突检查 → 保存。模型提取须校验结构和长度，历史与资料一律当数据，不当管理指令。
读取：先施加隔离和有效性过滤，再检索当前相关记录，限制条数与上下文预算；必要时含事件时间与来源。不确定就询问，不能编造回忆。
候选区与正式区分离；只有已确认或规则允许的非敏感事实进入默认召回。密钥、验证码不进入记忆。

管理命令：/记忆、/记住 内容、/纠正 记忆ID 新内容、/忘记 记忆ID、/暂停记忆、/恢复记忆。
仅能管理本人记忆；角色管理仅指定管理员。关闭记忆时停止新增长期记忆，近期上下文是否保留须明确提示。
纠正保留修订关联；删除清除正文、索引和受影响摘要，并阻止从原始消息重新提取。备份恢复后先执行删除记录再开放聊天。
默认原始消息保留30天，摘要与确认记忆保留到用户删除；本地备份保留7天。清理任务按这些期限实际执行，界面或命令需说明备份中的延迟清除。

## 对话及关系状态

顺序：校验身份 → 去重 → 入队与合并 → 获取限定上下文 → 检索记忆 → 组装提示 → 生成 → 发送 → 核对回执 → 提取候选记忆。
调用失败不得保存为成功回复；发送失败不得记作用户已经收到。入站事实与发送结果分开记录。
关系阶段为初识、熟悉、明确恋爱；不声称这代表程序真实情感。阶段变化由明确对话确认并留来源，可撤回。
主动问候默认关闭，未来需频率、时区、免打扰、关闭入口与发送授权。

## 配置、数据与 Git

服务只监听127.0.0.1；指定用户白名单，令牌非空且随机。QQ 接入组件和登录数据留在 runtime，不进入仓库。
.env 只本机读取，不写日志、文档、测试快照或导出。聊天不开放文件执行、Shell 或任意工具权限。
characters 只放可公开的虚构设定，个人偏好与真实经历存 data，不混入角色文件。
源码、测试、非敏感设计文档、依赖清单进入 Git；.env、data、runtime、日志、备份、导出、虚拟环境排除。
Git ignore 不负责清理已经跟踪或提交的文件；首次提交及每次推送需复核暂存清单和凭据检查。私有仓库也不能上传密钥。

## 实施阶段与验收

P1 稳定底座：模块化迁移、授权白名单、队列、去重、回执、持久化用量、角色配置、启停脚本。先保留旧启动方式可回退，不重启 NapCat 除非必要。
验收：授权用户真实往返；非授权与群消息不调用模型；连续消息不丢；重启后额度不重置；角色配置确实进入实际请求。

P2 记忆闭环：数据库迁移、上下文持久化、记忆管理命令、候选确认、FTS检索和备份清理。
验收：重启保留、修改替代旧事实、删除不重生、跨用户隔离、恢复后重放删除；模型请求不含无关用户信息。

P3 自然相处：细化许知宁设定、反馈培养、明确关系状态与固定对话对比集。
验收：对比倾诉、闲聊、分歧、纠错、亲昵与记不清场景；记录用户反馈，不将主观效果宣称为真实意识。

P4 语音与App：先验证QQ音频收发和授权音色，再接识别与合成；App显式身份绑定。另行设计验收。

本轮仅落盘设计与Git忽略规则，不安装插件、不修改bot.py、不更改已在线服务。
