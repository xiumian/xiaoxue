本轮不执行上游安装入口，不启动第二个QQ机器人，不接手机、群聊或共享记忆。

## 执行顺序

1. 保存选定源码与哈希到runtime/research；仅审阅humanize/role/brain/memory/index/wake。移植部分保留MIT许可证与归属。
2. 先编写tests/test_companion_merge.py：拆条不丢字、关闭开关、合并连续输入、合并上限、用户隔离、部分发送失败、重启送达历史；运行确认失败。
3. 增加app/humanize.py：从上游split逻辑适配，保留短句合并与最多条数，保护链接/代码块；不复制随机长等待和深夜变慢。
4. 增加SQLite批次与逐条回执表，不修改已有历史语义。批次最多合并8条、4000字；静默窗口900毫秒，硬上限3秒。接收循环保持可读回执。
5. Bot按用户合并后只调用一次模型；拆条逐条确认，失败停止后续、不重发。只有已确认的文本进入上下文，部分成功不当成完整回复。
6. 小范围丰富角色语感示例，不改变年龄、关系、身份透明等已确认设定。对同一模型与问题进行独立场景A/B；原始结果仅本机保存，不宣称客观更像人。
7. 运行离线回归与真实WebSocket模拟；对照固定上游split输出，记录有意差异。
8. 备份本机数据库和配置，只重启聊天进程；确认QQ连接，等待用户真实体验验收。
9. 脱敏验收文档、源归属、代码与测试提交Git；网络不可用则如实保留本地提交。

## 开关与验收

- MERGE_WINDOW_MS=0：关闭合并；SPLIT_ENABLED=false：整段发送；SEND_GAP_MS=0：无条间停顿。
- 新增表兼容旧数据，回退代码仍能读取旧turns；禁用开关即可退回原发送行为，无需删除数据库。
- 验证命令：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v`。
- 过关条件：连续短句只触发一次生成且顺序不乱；限长不丢后续；每条回执有状态；失败后不发送下一条；不同用户互不混入。
- 语言自然度由用户试聊判断，模型直连和拆条测试不等于QQ实际效果。
