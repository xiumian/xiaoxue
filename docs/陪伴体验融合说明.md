# 陪伴体验融合 · 使用与回退

## 合并方式

继续运行原Python机器人。只适配AI Companion Kit的回复拆条方法，参考其输入合并和角色示例思路。
固定上游版本和MIT归属见third_party/ai-companion-kit/NOTICE.md；没有执行安装脚本、npm安装、手机工具或第二套QQ入口。
上游参考源码仅供离线对照，不由在线程序加载。

## 当前配置

本机.env中：

```ini
MERGE_WINDOW_MS=900
MERGE_MAX_WAIT_MS=3000
SPLIT_ENABLED=true
SEND_GAP_MS=500
```

收到首条消息后等待900毫秒，窗口内有新消息则继续等，最多3秒、8条、合计4000字；越界部分留到下一轮，不截掉。用户和机器人账号之间隔离。
生成回复后默认最多拆3条；短回复仍一条。链接、代码块和列表不拆；不会为了拆条自动扩写短回复。
没有随机打字延迟、半夜故意变慢或伪造“正在输入”。500毫秒只是条间间隔，不代表已实现全局每分钟限流。

发送每条都等待OneBot成功回执；失败/不确定时停止后续发送，不自动重发。只将成功前缀纳入上下文。因网络超时，用户可能实际收到但服务未确认，系统会保守处理。
数据库新增outgoing_parts表及turns.context_user_text列；保留原始入站消息，合并后的上下文另存，不重复计为多次生成。

## 回退

在本机.env设置MERGE_WINDOW_MS=0、SPLIT_ENABLED=false、SEND_GAP_MS=0，然后运行scripts/bot.ps1 restart；不需要重启NapCat或删除数据库。
这会关闭本轮发送体验功能，但保留角色v2。角色v1基线保存在本机runtime/evaluations/persona-before-merge.md，也可通过Git提取旧版角色文件。
不建议直接用旧代码覆盖新代码；旧版不理解部分送达状态和合并上下文字段。
部署备份仅本机保留，含私密数据，不提交、不发给别人；测试完成后按数据保留要求清理。本轮不启用自动恢复。

## 验证命令

- Python回归：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v`
- 上游拆条对照：`node scripts/compare_upstream_split.mjs`，调用前校验固定参考文件SHA-256。
- 模型A/B：`scripts/evaluate_companion.py`，需显式提供baseline/candidate路径。会产生模型调用费用，原始结果只写runtime/evaluations，不写真实聊天数据库。

## 不包含的能力

事实提取、语义长期记忆、关系成长、自动日记、主动问候、群聊与手机控制均未引入。
回复更短、分条更自然不等于理解更好；仍需主人连续试聊验收。
